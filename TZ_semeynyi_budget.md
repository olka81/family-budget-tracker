# Техническое задание: веб-приложение учёта семейных расходов

## 1. Цель проекта

Основная цель — учебная: углубить знания C# (ASP.NET Core, EF Core) и работы с реляционными БД (PostgreSQL) на практическом проекте. Побочный, но реальный результат — рабочий инструмент для учёта семейных трат.

## 2. Функциональные требования

### 2.1. Аутентификация
- Вход через email/пароль.
- Вход через Google-аккаунт (OAuth) — как основной/предпочитаемый способ.
- *Примечание:* оба варианта стандартно поддерживаются ASP.NET Core Identity + внешним провайдером, дополнительных затрат не требуют (Google OAuth client создаётся бесплатно в Google Cloud Console).

### 2.2. Семейные группы
- Пользователь может создать семейную группу.
- Пользователь может присоединиться к существующей группе (по приглашению/коду).
- **Права участников: все члены группы равны** — любой участник может добавлять, видеть и редактировать все покупки группы. Разделения на админа и обычных участников в MVP нет.
- **Пользователь без семьи:** при регистрации у пользователя автоматически создаётся "личная" группа из одного человека — отдельного режима "без группы" в системе нет. Это упрощает модель данных: покупки всегда привязаны к группе, а не иногда к пользователю напрямую, а переход от одиночного использования к семейному — это просто приглашение второго участника в уже существующую группу, без миграции данных.
- **Один пользователь = ровно одна группа** — членство в нескольких группах одновременно не предусмотрено (решено на этапе проектирования схемы).

### 2.3. Учёт покупок
- Добавление покупки: дата, сумма, продавец/описание, категория, подкатегория, заметка.
- Категории — иерархия **произвольной глубины** (категория → подкатегория → под-подкатегория и т.д., без жёсткого ограничения в два уровня), задаются заранее (набор по умолчанию) с возможностью добавления своих.
- **Валюта:** в MVP используется одна валюта (EUR — Болгария перешла на евро). Структура данных закладывается с учётом будущей мультивалютности (у каждой покупки/счёта есть явное поле валюты, а не жёстко прошитое значение), но конвертация и работа с несколькими валютами одновременно — не в MVP.
- **Импорт через Claude Cowork:** сканы чеков обрабатываются в Cowork, на выходе — CSV-файл с покупками, целиком загружаемый в приложение через отдельный экран импорта (с превью перед подтверждением и проверкой на возможные дубли). Покупка в общем виде должна содержать: дату, сумму, продавца, категорию (с учётом произвольной глубины иерархии), заметку. **Точный формат CSV (набор колонок, кодирование пути категории, разделители) зафиксируем после проектирования структуры БД** — формат импорта должен следовать из схемы данных, а не наоборот.

### 2.4. Отчёты
Приоритет на MVP — один отчёт, остальное в бэклог:
1. **(MVP) Разбивка трат по категориям за выбранный период** — сумма и доля по каждой категории/подкатегории за произвольный диапазон дат.
2. (Бэклог, после MVP) Сравнение периодов — например, этот месяц vs прошлый.
3. (Бэклог, после MVP) Разбивка по членам семьи — кто сколько потратил.

### 2.5. Визуализация
- Не входит в MVP. Рассматривается как следующий этап после того, как отчёты в текстовом/табличном виде заработают.

## 3. Нефункциональные требования

- **Бюджет:** лицензии на ПО — только бесплатные, без исключений. Для хостинга — приоритет бесплатным тарифам; если бесплатного варианта не хватит (например, ограничения Render/Neon станут проблемой), выбираем самый бюджетный платный вариант, а не первый попавшийся.
- **Не хранить данные банковских счетов** — только сведения о покупках (сумма, категория, продавец, дата).
- Приложение — веб (не десктоп), доступ с браузера.
- Проект должен быть **деплоящимся** (не просто локальный прототип) — это часть учебной ценности.

## 4. Технологический стек (зафиксировано ранее)

| Слой | Технология |
|---|---|
| Backend | ASP.NET Core |
| Frontend | Blazor Server (сознательный выбор — фокус на бэкенде, а не на изучении отдельного JS-фреймворка) |
| ORM | Entity Framework Core |
| БД | PostgreSQL |
| Хостинг приложения | Render (бесплатный тариф) |
| Хостинг БД | Neon (постоянный бесплатный тариф) |
| Тестирование | xUnit + Testcontainers |
| Вспомогательный AI-инструмент | Claude Cowork — для парсинга чеков в структурированные данные |

## 5. Не входит в MVP (бэклог на будущее)

- Мультивалютность как реально работающая функция (только закладывается в структуру).
- Роли/права внутри группы (админ vs участник).
- Сравнение периодов и разбивка по членам семьи в отчётах.
- Визуализация (графики).
- Мобильное приложение / адаптация под мобильные устройства как отдельная задача.

## 6. Открытые вопросы (решаются на следующих этапах, не сейчас)

- Точная структура таблиц БД, типы полей, индексы — отдельный шаг плана.
- Точный формат CSV для импорта (колонки, кодирование пути категории) — зависит от структуры БД, решается сразу следом за ней.
- Формат приглашения в группу (код, ссылка, email-приглашение).
- Логика определения дублей при загрузке из Cowork.
